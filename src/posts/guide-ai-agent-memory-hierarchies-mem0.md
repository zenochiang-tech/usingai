> 尽管如今主流大模型的上下文窗口已经扩展到 128k 甚至 1M+ Token，许多开发者依然发现：直接将所有历史记录扔进上下文（Prompt Stuffing），会导致严重的“大海捞针”遗忘、注意力漂移以及昂贵的延迟与成本。
> 
> 真正具备类人连续智能的 Agent，必须像人脑一样拥有**分层记忆架构（Hierarchical Memory）**。
> 
> ### 1. 记忆的三层抽象模型
> 
> - **工作记忆（Working / Sensory Memory）**：
>   - **载体**：当前会话的上下文窗口（Context Window）。
>   - **职责**：维护当前多轮对话的最关键信息与短期变量，任务完成后即刻压缩。
> - **情境记忆（Episodic Memory / 事件记忆）**：
>   - **载体**：结构化时序日志库 + 向量索引。
>   - **职责**：记录“用户在特定时间点做过什么、遇到过什么问题”。支持按时间线与因果关系检索。
> - **语义与实体记忆（Semantic Memory / 知识图谱）**：
>   - **载体**：实体-属性-关系图谱（Knowledge Graph / Mem0 范式）。
>   - **职责**：提炼持久性事实（如“用户的技术栈是 Rust 和 Next.js”、“偏好暗黑模式界面”），与具体对话时段解耦。
> 
> ### 2. 动态记忆更新流水线（Memory Pipeline）
> 
> 一个高效的记忆系统不应在每次查询时全量遍历，而应采用异步生命周期管理：
> 
> 1. **提取（Extraction）**：对话结束后，异步调用轻量模型抽取“用户核心事实”与“关键意图转变”；
> 2. **冲突消除与去重（Conflict Resolution）**：若用户说“我现在改用 Tailwind 了”，自动失效原先“偏好手写 CSS”的旧记忆实体；
> 3. **相关性衰减（Recency & Importance Decay）**：结合时间衰减函数与语义相似度（Hybrid Retrieval），确保注入上下文的永远是最精准的记忆片段。
> 
> 分层记忆不仅让 Agent 具备真正的持久化个性，更是走向跨平台、跨应用终身伴随助手的核心基石。
