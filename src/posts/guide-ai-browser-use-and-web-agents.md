> 过去编写网页爬虫或自动化测试脚本（如 Selenium、Puppeteer），最令人头疼的莫过于前端 DOM 结构的频繁变动：一个 class 类名更新或按钮位置微调，整个脚本便轰然崩溃。
> 
> 而以 **Browser-Use** 为代表的新一代**多模态视觉驱动 Web Agent**，彻底改变了与浏览器的交互方式——大模型不再依赖脆弱的 CSS 选择器，而是直接“用眼睛看懂网页屏幕截图”，通过视知觉与语义理解完成自主点击、输入与导航。
> 
> ### 1. 核心工作原理：观察-思考-动作循环（OODA Loop）
> 
> 一个端到端的视觉浏览器 Agent 主要包含三个关键管道阶段：
> 
> 1. **DOM 高亮标记与元素编号（Set-of-Mark Prompting / SOM）**：
>    在无头浏览器中运行一段轻量 JavaScript，为当前视口内的所有可交互元素（按钮、输入框、下拉菜单）自动贴上带有数字编号的半透明边界框（Bounding Box）。
> 2. **视觉输入与决策推理（Multimodal LLM Reasoning）**：
>    将带有编号标注的高清网页截图发送给具备视觉理解能力的大模型（如 Claude 3.5 Sonnet 或 GPT-4o），模型根据用户目标（如“帮我比价三家云服务商的 GPU 租赁月费并制表”）输出结构化指令：`click(23)`, `type(14, "H100 NVL")`。
> 3. **动作执行与自适应验证（Action & Self-Correction）**：
>    执行点击后再次截图比对。若触发了反爬验证码（CAPTCHA）或弹窗遮罩，Agent 能通过视觉反馈自主识别并尝试关闭干扰弹窗。
> 
> ### 2. 生产落地实战避坑要点
> 
> - **长页面视口滚动控制**：避免单次注入过长页面，采用动态视口滚屏（Incremental Viewport Scrolling），让模型逐步探索页面下半区。
> - **高敏感凭证安全隔离**：涉及账户登录时，坚决避免将明文密码硬编码进 Prompt，推荐使用预加载已认证会话 Cookies 或隔离的身份委托代理。
> - **确定性降级机制**：对于具有标准 REST API 的平台，优先调用 API；仅在缺乏标准接口的长尾网页交互场景中调动视觉 Agent，兼顾速度与成本效益。
> 
> 从文本输出到真正接管屏幕像素，AI 正在从“交谈者”蜕变为真正能替你打理一切现实事务的超级行动者。
